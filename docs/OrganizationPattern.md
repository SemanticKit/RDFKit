# Package Organization

## Targets

| Target | What it holds |
|---|---|
| `RDFCore` | The RDF 1.2 data model at the boundary: `Graph`, `Dataset`, `Triple`, `SubjectTerm`, `ObjectTerm`, `Literal`, `BlankNode`, isomorphism. Also `Values`, the set of a many-valued property's values (D5), and the `Ontology` and `Content` protocols with `ContentBuilder`. |
| `RDFKit` | RDF, RDFS and OWL, generated by `RDFTranslatorPlugin` from `RDF/rdf.ttl`, `RDFS/rdfs.ttl` and `OWL/owl.ttl`, and the `@Ontology` macro with the DSL declarations it reads (`DSL/Declarations.swift`). |
| `RDFKitMacros` | `@Ontology` and `@OntologyBody`. `OntologyParser` reads the body's syntax, and the generators of `OntologyGeneration` write the Swift. |
| `OntologyGeneration` | `Schema`, which closes statements under the published semantics, and `SwiftSchema`. Also `ClassGenerator` and `PropertyGenerator`, which both the macro and the translator use. `SemanticsEmitterPlugin` generates `publishedSemantics` from the W3C documents in `W3C/`. |
| `SemanticsEmitter` | Reads the entailment and rule tables of RDF 1.2 Semantics, OWL 2 RDF-Based Semantics and OWL 2 Profiles into `publishedSemantics`. |
| `RDFTranslator` | Translates RDF documents into Swift: the protocols of their classes and properties, the classes of their individuals (`Individuals`) and their `ontology` description (`Description`). `RDFTranslatorPlugin` runs it on every target that has `.ttl` or `.rdf` documents. |
| `RDFFormats` | N-Triples, Turtle and RDF/XML decoders and encoders, with grammars generated from the specifications' EBNF (`Grammars/`, `EBNFTranslatorPlugin`). Also `GraphEncoder`, which encodes any `Encodable` individual as a graph. |
| `XSD` | The XML Schema datatypes RDF uses, as Swift value types (D6), and their value spaces (`ValueSpaces/`) and lexical mappings. `XSDEmitterPlugin` generates the datatypes from the W3C documents in `W3C/`, as `units.txt` lists them. |
| `XSDDefinitions`, `XSDEmitter` | Read the XML Schema documents, and generate the datatypes' types, facets and `init(lexicalForm:)`. |

## Where the Vocabularies Live

Each vocabulary RDFKit translates is a document stored byte for byte as its source gives it. Next to it is a `README.md` with the source, the commit or date it was retrieved, and its sha256. A document at a target's root is module-level. A document in a subdirectory is nested in a namespace named after the directory: `RDFKit/RDF`, `RDFS`, `OWL`.

## Rules

1. The Swift for a vocabulary is generated from its documents, never written by hand (rule 0).
2. What a term is, a class, a property, the root or a literal class, comes from the published semantics, not from names in the generators.
3. One file per type or concern, with `// MARK:` sections where a file has several parts.
4. Follow the Swift API Design Guidelines, and document with DocC.
